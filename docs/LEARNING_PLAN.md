# GTE-Net 独立复现学习计划

建立日期：2026-10-13。状态：教学路线已建立，能力诊断待完成。

文档位置：Markdown 学习文件统一放在 `docs/`；本文反引号中的路径以项目根目录为基准。`lessons/`、`reference/`、`assets/` 及未来的练习/记录目录仍位于项目根目录。

## 1. 最终目的

以 [docs/MISSION.md](MISSION.md) 为准：用户自己完成 DEAP Valence 二分类复现，能够解释、检查和排错，而不是照抄助手给出的整套答案。终点包含窗口级复现和受试者级独立评估；不以达到上游某个准确率作为学习通过条件。

当前技术依据是本地 `DatasetProcessSave.py`、`GTE_train.py`、`model_optimized.py`，以及 [docs/REPRODUCTION_PROTOCOL.md](REPRODUCTION_PROTOCOL.md)。教学计划不替代实验协议。模型结构、张量维度和命令在每次出题前重新核对当前代码；阶段 B 的实现与实验定义仍待设计。

## 2. 如何安排每次学习

一次只解决项目中一个具体的小问题，以用户亲自编写可运行代码为主。任务大小按实际反馈调整，不以固定时长限制实现。

1. 先读 [docs/LEARNING_PROGRESS.md](LEARNING_PROGRESS.md)，确认当前题、待复测项和已有证据。
2. 把当前模块拆成可实现的小任务，说明它解决的项目问题以及和前后模块的连接；基础诊断通过用户代码、运行结果与实际卡点完成。
3. 给出输入、输出、函数接口或必要骨架、约束、验收示例和所需资料；按需要讲解最少的知识，不提前给完整实现。
4. 用户动脑筋设计并编写代码，亲自运行，提交代码和实际输出。
5. 根据实现与结果评审；卡住时按“指出位置 → 提醒概念 → 给局部示例 → 完整解释”逐级提示。
6. 概念问题只围绕刚实现的功能、出现的错误或设计选择展开；需要迁移或复测时，让用户改变需求、扩展代码或修复问题，不单独用理论问答作为推进门槛。

练习在 `exercises/<题号>/` 中进行，研究代码改动由用户亲自实施；原始数据默认只读。新课使用 `lessons/` 中编号的 HTML，术语与速查材料放在 `reference/`，复用 `assets/` 中的组件。已有第一课保留。

## 3. 阶段路线与通过标准

下面是出题的范围与阶段验收，不是要求用户一次完成的作业清单。每阶段可拆成多道小题，不预先固定总题数。

| 阶段 | 要获得的能力 | 练习与交付物 | 无完整答案时的通过标准 |
| --- | --- | --- | --- |
| S0 起点诊断与工作环境 | 区分终端、解释器、虚拟环境；找到数据处理与训练入口 | 判断少量代码、定位文件、自己检查解释器；建立基础缺口清单 | 能选择项目解释器，读懂报错所在文件和行；不会的基础有明确补课任务 |
| S1 数据读取与标签 | 理解字典、数组形状、切片、受试者/试验/通道/采样点和标签阈值 | 自己写一个读取单受试者的短脚本，输出形状；练习阈值边界 | 能解释各维度，改变切片后预测并核对形状；正确处理 Valence 等于 5 的情况 |
| S2 基线与窗口 | 把秒、采样点、数组位置和窗口对应起来 | 单试验切窗检查；自己推导并检查首末位置、数量、标签对应关系 | 无越界、无基线混入刺激窗口；能发现故意给出的偏移错误，并解释修复依据 |
| S3 特征与缓存 | 理解时域/DE 两路输入、有限值、缓存用途与实现差异 | 单真实窗口特征检查，再检查缓存样本数与结构 | 能追踪两路输入来自同一窗口；能说明 `filtfilt` 与 `lfilter` 不可默认等价，判断缓存是否匹配配置 |
| S4 Dataset、批次与划分 | 理解 `__len__`、`__getitem__`、DataLoader、批次维度和划分单位 | 追踪一个样本到一个 batch；检查窗口级划分并解释风险 | 能预测实际 batch 形状、检查标签类型，区分窗口数和受试者数；说明当前验证集不能回答未见受试者泛化问题 |
| S5 模型前向 | 读懂 CNN、DE 映射、拼接、GAT、注意力汇总、Transformer 和分类输出的连接 | 逐模块补张量形状，用真实 DEAP 窗口检查前向 | 能追踪输入到 logits；能解释当前默认 `n_slices=1` 的限制，定位给定的维度错误；无需从零推导所有数学公式 |
| S6 训练、验证与排错 | 理解 loss、反向传播、优化器、训练/验证模式、指标和保存 | 手算一组完整预测的 Accuracy；读训练循环；自己运行冻结的 1 epoch 冒烟实验 | 能检查训练/验证/输出文件闭环并记录实测信息；区分 logits、预测类别和标签；遇到异常能用最小检查定位 |
| S7 窗口级复现与结果报告 | 管理配置、随机性、资源、长训练和上游比较 | 在冒烟通过后分步完成协议规定的中程/长训练，写一份可复查报告 | 报告含命令、版本/工作树、划分、样本数、指标范围和产物；明确单次与重复运行，解释与上游值的差异而不保证复现数值 |
| S8 受试者级独立评估 | 设计分组、保留身份、避免泄漏、正确选择模型与测试 | 先冻结阶段 B 协议，再由用户实现并检查划分、随机种子、预处理及指标，执行评估 | 受试者集合无交叉；测试集不参与参数/epoch 选择；归一化等拟合只用训练数据；汇总完整预测的 Accuracy、Macro-F1、混淆矩阵和逐受试者结果 |
| S9 独立毕业任务 | 独立组织并交付整个复现 | 在新的隔离工作目录或环境中，保留原数据，自己从环境检查做到结果报告；助手只评审 | 窗口级复现与受试者级评估均有真实运行证据；能解释设计、复查产物并独立定位一个真实或安全模拟的故障 |

S6 的冻结命令见协议第 7.3 节；S7 按 Gate A1–A4 推进，长训练前评估设备与耗时。资源不足时记录阻断，可验收已经完成的能力，但不能把未执行的实验标记完成。S8 的主分析方案、重复次数与汇总方法在执行前确定，不在此预填结果。

## 4. 出题要求

- 每题有稳定编号，如 `S1-E01`；写明目标能力、前置知识、当前代码位置、题目、交付物与验收标准。
- 以项目模块编程题为主，题目具有类似 LeetCode 的明确任务、输入输出和验收条件，但使用实际数据并逐步连接为复现流程。阅读、预测和解释只作为实现与排错的辅助，不连续安排脱离编程任务的理论问答。
- 题目只检验本次目标；不熟悉的语法先教，不用隐藏前提制造困难。
- 用户先尝试后再提供答案。给过完整答案后，用新的小变式重新评估，不以原题重述为独立完成。
- 阶段验收使用未做过的组合任务，允许查官方文档与自己的笔记，记录助手帮助；独立不等于死记 API。
- 下次会话或隔至少一天，结合实际代码安排一个小变式或修复任务复测；之后隔几次学习再复测关键能力。间隔按用户学习频率调整。
- 错误先区分概念、语法、操作、环境或题目表述问题，修正最小缺口后再推进。
- 根据表现调整题目数量和难度。改路线写明原因；不擅自更改 MISSION 中的最终目标。

## 5. 记录体系

| 文件 | 用途 | 更新时机 |
| --- | --- | --- |
| `docs/MISSION.md` | 为什么学、最终成功是什么 | 用户明确改变目标时 |
| `docs/LEARNING_PLAN.md` | 阶段路线、出题与验收规则 | 发现需要调整路径时，追加调整原因 |
| `docs/LEARNING_PROGRESS.md` | 当前题、能力状态、待复测和下一步；新会话首读 | 每次收到作答或实际学习活动后 |
| `learning-sessions/YYYY-MM-DD-NN.md` | 当次题目、答案证据、操作结果、提示、反馈与接续位置 | 实际发生学习活动后；不编造历史 |
| `learning-records/NNNN-<slug>.md` | 真正表现出的理解、基础披露或纠正的误解 | 有证据值得影响后续教学时；不记“已讲过”流水账 |
| `docs/EXPERIMENT_LOG.md` | 真正运行的验证与实验 | 有实际执行证据时，遵守项目实验记录规则 |

实验完成不自动等于用户掌握；用户掌握某个概念也不自动等于实验完成。助手代做与用户亲自完成分别注明。对没有看到的本地运行，可记“用户报告”，待输出核对后再记“已核对”。个人笔记由用户保留，本计划不覆盖它。

## 6. 新会话接续规则

教学请求先读 MISSION → LEARNING_PLAN → LEARNING_PROGRESS → NOTES，再读进度引用的最近 session/record、当前题与相关代码。实验前额外核对 CONTEXT、AGENTS、协议、实验日志和工作树。

缺记录时只追问缺失的最小证据，不推测已掌握、不重头讲整套课程。进度中的“下一步唯一动作”是恢复入口。用户在新会话可直接说：“按 docs/LEARNING_PROGRESS.md 继续教学”。
