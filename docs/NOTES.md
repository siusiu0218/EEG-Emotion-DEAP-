# 教学偏好

- 用户希望一步步亲自操作，并知道每一步在做什么。
- 先说明学习目的，再解释少量实际代码；不要一次列出所有参数。
- 理解检查围绕用户刚编写的代码和解决的项目问题展开，不以单独理论问答作为学习主线。

## 2026-10-13：以做题获得独立复现能力

- 用户希望助手规划学习过程、持续出题与记录进度，以便上下文变长或换会话后仍围绕独立完成项目。
- 以 `docs/MISSION.md` 为目标、`docs/LEARNING_PLAN.md` 为路线、`docs/LEARNING_PROGRESS.md` 为接续入口。
- 一次一个小任务，先让用户尝试，按需要逐级提示；减少帮助后用新题和后续复测确认掌握。
- 只记录有作答/操作证据的能力；不将讲解、助手代做或脚本能运行等同于用户掌握。

## 2026-10-13：纠正做题形式

- 用户希望将大项目拆成模块，每个模块再拆成类似 LeetCode 的编程任务，让自己思考并写代码解决实际问题。
- 每题明确问题背景、输入输出、接口、限制和验收条件；助手提供必要知识与逐级提示，评审代码和运行结果。
- 理论问题只作为实现、排错或设计选择中的附带思考，不连续提问基础概念，不把口头预测当作主要交付物。
